01

Overview

Metro Control is a compact metro operations game that runs inside the Chrome extension popup. Players build routes between fictional stations, purchase and operate fictional trains, move simulated passengers, manage crowding and transfers, respond to service incidents, upgrade stations, and progress through service days.

The current release is designed as a self-contained local game. Its core simulation is executed by JavaScript included in the extension package. Normal gameplay does not require an online account, cloud save, remote game server, analytics service, advertising network, social platform, or developer-operated API.

Summary: Metro Control saves its fictional transit network locally in the browser. The developer does not receive the local game save through normal gameplay, and the extension does not need access to the websites the user visits.
02

Scope of this policy

This policy applies to Metro Control version 1.0.0 and to the code and assets packaged with that version, including the popup interface, transit simulation, route-building system, passenger simulation, station queues, train operations, incidents, progression, service-day scoring, tutorial state, and local save.

This policy does not govern Google Chrome, the Chrome Web Store, the user's Google account, the operating system, enterprise browser management, device backup software, security products, or unrelated websites and applications. Those products may process data independently under their own settings and policies.

If a future release adds materially different functionality—such as accounts, cloud synchronization, multiplayer, remote AI, analytics, advertising, website integration, or new Chrome permissions—this policy should be updated to describe the new behavior.

03

Local-first architecture

Metro Control stores the current game state in the extension's own browser origin using ordinary localStorage. The current save key is:

localStorage key
metroControlStateV1

The key is an implementation detail used to find the saved game. It is not a user account number, advertising identifier, browser fingerprint, or identifier intended to track a person across websites or services.

The simulation can continue across popup sessions because the game periodically serializes its state to this local key and saves again when the popup is being closed. The extension then reads the same local state the next time it opens.

Metro Control does not currently provide a developer-operated cloud backup. As a result, the developer normally cannot restore a game after the local browser data has been deleted.

04

Information collected by the developer

During normal use of version 1.0.0, Metro Control does not collect the local game save for the developer. Opening the popup, building routes, buying trains, moving passengers, completing a day, resolving an incident, or changing the network does not automatically transmit those actions to a developer server.

The extension does not intentionally collect names, email addresses, postal addresses, phone numbers, passwords, authentication tokens, payment information, health information, biometric information, precise location, browsing history, search history, website content, private messages, Chrome account identifiers, or other unrelated personal information.

Metro Control also does not automatically report gameplay telemetry such as session duration, number of stations served, routes created, credits earned, riders delivered, incidents resolved, service reliability, or service-day scores.

06

What the local game save contains

The local save contains the data required to reconstruct the fictional network and simulation. Depending on progress, that state can include:

  • the save-format version;
  • a locally generated random seed and random-number-generator state;
  • the current service day and in-game clock;
  • simulation timing, speed, paused/running state, and whether service has started;
  • fictional credits, reliability, and score;
  • created metro lines, line identifiers, line colors, and station sequences;
  • fictional trains, their line assignment, route position, direction, dwell time, capacity, and passengers currently onboard;
  • station upgrade levels, passenger queues, demand accumulation, and overload timing;
  • active fictional service incidents;
  • service-day summary information;
  • tutorial progress;
  • locally generated IDs for simulated passengers, trains, and incidents;
  • aggregate gameplay statistics described below.

These values describe a simulated transit system. They are not derived from the user's real transit card, real commute, real city, GPS coordinates, physical movement, financial account, or browsing behavior.

07

Fictional passengers, destinations, and route finding

Metro Control generates fictional passengers as part of the game simulation. These passenger objects can include an internal ID, a fictional destination station, waiting/journey state, and information required to simulate transfers or delivery to a destination.

Passenger routing is calculated from the fictional metro graph built by the player. Route finding does not use the user's location, travel history, Google Maps information, contacts, calendar, or real transport data.

Station queues and onboard passenger lists may be stored as part of the local save so the simulation does not need to discard an active service day whenever the popup closes.

No real passenger information: terms such as “passenger,” “destination,” “journey,” “station,” and “transfer” refer only to objects inside the game simulation.
08

Gameplay statistics and progression

The game maintains local aggregate statistics needed for scoring, progression, summaries, and simulation balancing. These can include values such as:

  • fictional passengers generated, delivered, or missed;
  • transfers completed;
  • total simulated journey time;
  • today's delivered/generated/missed passenger counts;
  • fictional service revenue;
  • service days completed;
  • lines built and trains purchased;
  • station upgrades;
  • incidents resolved.

These statistics stay in the local game state. They are not a developer analytics profile and are not automatically uploaded for measurement, marketing, advertising, user segmentation, or cross-product tracking.

09

Storage, persistence, and retention

The saved game remains in the Chrome browser profile so that progress can persist after the extension popup is closed. The developer does not set a server-side retention period because the current version does not maintain a remote game-save database.

Local information can remain until Chrome or the user removes or replaces it. This may occur through normal game saves, clearing extension-origin browser data, deleting or resetting the browser profile, uninstalling the extension, enterprise-management actions, or other browser/device maintenance.

Chrome, the operating system, enterprise-management software, migration tools, or device-backup software may independently copy or preserve browser-profile files according to their own behavior. Metro Control does not control those external systems.

No cloud recovery: because the developer does not receive the local save during normal play, the developer generally cannot recover progress after local data is removed.
10

Chrome permissions

Metro Control version 1.0.0 uses Chrome Manifest V3 and requests no extension permissions and no host permissions.

The manifest does not request permissions such as tabs, activeTab, history, scripting, cookies, downloads, notifications, geolocation, or Chrome's extension storage API permission.

The game instead uses ordinary web-platform capabilities available within its own extension popup, including DOM rendering, Canvas graphics, timers, animation frames, and the popup origin's localStorage.

11

Website, tab, and browsing access

Metro Control does not need the page behind the toolbar popup in order to operate. The current version has no content scripts and no host permissions.

It does not read or modify:

  • the URL or title of the active tab;
  • text, images, forms, links, or DOM content on web pages;
  • Chrome browsing history or search history;
  • website cookies;
  • website localStorage or sessionStorage;
  • information typed into unrelated websites;
  • download history or bookmarks.

The localStorage used for metroControlStateV1 belongs to the extension's own origin and is separate from the storage of unrelated websites.

12

Network activity and remote code

The reviewed Metro Control package does not use fetch, XMLHttpRequest, WebSocket, or a developer API for its gameplay. The current game logic, interface, styling, and icons are packaged with the extension.

The package does not load remote JavaScript, remote CSS, remote fonts, online maps, real transit feeds, remote AI, social-login libraries, analytics endpoints, or advertising resources.

Chrome itself may communicate with Google for installation, extension updates, Chrome Web Store functions, security, account features, or browser services. Operating systems, networks, administrators, and security products may also create their own network traffic. Those communications are outside Metro Control's game implementation.

13

Analytics, tracking, cookies, and advertising

Analytics and telemetry

Metro Control version 1.0.0 does not include Google Analytics, Firebase Analytics, Mixpanel, Amplitude, Segment, PostHog, or a comparable analytics SDK. It does not automatically submit gameplay metrics to the developer.

Advertising

The extension does not contain third-party advertising, an ad network, retargeting code, behavioral advertising technology, or advertising identifiers.

Cookies and fingerprinting

Metro Control does not request Chrome's cookies permission and is not designed to fingerprint the browser or device, correlate a person across websites, or create a cross-site behavioral profile.

Crash reporting

The reviewed package does not include a third-party crash-reporting SDK that automatically uploads game state, device identifiers, or diagnostic records to the developer.

14

Sharing, sale, and disclosure

The developer does not sell, rent, license, or provide the local Metro Control game save to advertisers, data brokers, analytics companies, social networks, or marketing providers because the current version does not collect that save for developer use.

There is no online leaderboard, public player profile, multiplayer account, shared network, or automatic social-posting system in version 1.0.0.

If a user voluntarily takes a screenshot, records gameplay, copies information, or shares content through another application, that later sharing is controlled by the user and the separate service involved.

If the developer receives a lawful request for information, the developer can only provide information actually possessed. The local game state described by this policy is not maintained in a developer gameplay database during normal operation.

15

Security and data minimization

Metro Control minimizes privacy exposure by avoiding an account system, remote gameplay backend, analytics platform, advertising stack, broad browser permissions, and access to unrelated web pages.

The extension's game code and visual assets are packaged locally rather than retrieved as remote executable code during normal use.

Local browser storage should not be interpreted as an encrypted vault. A person or process with access to the same unlocked browser profile, operating-system account, browser files, or device backups may potentially access local extension data depending on the security of the device.

No software can guarantee absolute security. Users should keep Chrome and their operating system updated and use appropriate device security.

16

Deleting Metro Control data

Metro Control version 1.0.0 does not maintain a developer-side account that must be closed to remove the local game save. The primary stored state is the browser-local metroControlStateV1 value.

Local game data can be removed by clearing the extension's local site/origin data through browser tools, removing the associated browser profile, or uninstalling the extension subject to Chrome's data-management behavior.

Deleting local data removes the information needed to reconstruct saved progress, including network layout, routes, trains, passenger queues, incidents, credits, reliability, statistics, and progression. Because the developer does not have a normal cloud copy, deleted progress is generally not recoverable from the developer.

If Chrome, the operating system, an administrator, or a backup product has independently preserved browser-profile files, those copies are controlled by that separate system rather than Metro Control.

17

Children's privacy

Metro Control is a general entertainment game. It does not require a name, date of birth, public profile, online account, user-to-user messaging, precise location, or behavioral advertising profile.

The extension is not designed to solicit personal information from children or adults. Its stored objects represent fictional transit operations rather than real-world identity information.

18

Chrome, the Chrome Web Store, and other third parties

Metro Control runs on the Chrome platform and may be distributed through the Chrome Web Store. Chrome and the store are separate products operated independently from this extension and may process installation, update, security, account, diagnostic, or store-related information under their own terms and privacy practices.

Similarly, operating-system backup tools, enterprise browser management, antivirus products, device synchronization, and other third-party software can interact with browser-profile files independently. Metro Control does not control those products.
